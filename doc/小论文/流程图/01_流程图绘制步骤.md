# 流程图绘制步骤

## 1. 绘图目标

绘制一张上下对照的流程图：

- 上方为传统 CPU-SOCS 在线重构流程。
- 下方为本文 CPU-FPGA 协同 SOCS 在线重构流程。
- 两条流程使用同一输入掩模、同一组 SOCS 本征核、相同核数量和相同最终输出定义。
- 图中突出计算位置、数据组织、存储方式和在线执行延迟的差异。

图的中心结论是：本文没有改变 SOCS 数学模型，而是将重复执行的在线算子从 CPU 软件循环映射为 FPGA 固定网格流水线。

## 2. 先确定流程边界

绘图前将完整计算划分为三个阶段。

| 阶段 | 执行侧 | 主要任务 | 图中表现 |
| --- | --- | --- | --- |
| 离线光学预处理 | CPU | 光源生成、TCC 构建、特征分解、SOCS 核与权重导出 | 灰色虚线框 |
| 在线 SOCS 重构 | CPU 或 FPGA | 频域复乘、二维 IFFT、强度计算、加权累加 | 两条流程的主要对比区域 |
| 后处理 | Host CPU | FFTshift、傅里叶插值、中心裁剪和结果输出 | 流程末端 |

掩模 FFT 需要针对每个输入掩模计算。SOCS 本征核和权重只在光学配置变化时更新，可跨多个掩模窗口复用。

## 3. 画布和整体布局

1. 使用横向画布，建议比例为 `16:9` 或论文双栏宽图。
2. 画布分为上下两条等宽流程，中间使用细分隔线。
3. 上方标题写 `Conventional CPU-SOCS Flow`。
4. 下方标题写 `Proposed CPU-FPGA Collaborative Flow`。
5. 每条流程设置 `(a)` 至 `(e)` 五个图像节点，并保证上下节点纵向对齐。
6. 节点之间使用水平实线箭头；可复用数据使用虚线箭头。
7. 流程节点以图像为主，步骤名称放在箭头上方，尺寸和关键数据放在图像下方。

建议结构：

```text
Conventional CPU-SOCS Flow
(a) Mask -> (b) Mask spectrum and kernels -> (c) CPU per-kernel IFFT
         -> (d) CPU weighted accumulation -> (e) Final aerial image

Proposed CPU-FPGA Collaborative Flow
(a) Mask -> (b) Reusable optical data package -> (c) FPGA embedding and 2D IFFT
         -> (d) BRAM weighted accumulation -> (e) Host-FI aerial image
```

## 4. 绘制共享输入与离线分支

### 4.1 共享输入

上下两条流程的 `(a)` 都使用同一张二值掩模图，避免让读者误以为加速来源于输入差异。

在 `(a)` 到 `(b)` 的箭头上标注：

```text
Mask FFT
```

### 4.2 离线光学预处理

在主流程上方或下方增加一个较小的灰色虚线框：

```text
Optical configuration
        ↓
Source and pupil construction
        ↓
TCC construction
        ↓
Eigenvalue decomposition
        ↓
SOCS kernels Φk and weights σk
```

从 `SOCS kernels Φk and weights σk` 分别向两条流程的 `(b)` 连接虚线箭头，并标注：

```text
Precomputed and reused
```

不要把 TCC 构建画进 FPGA 在线路径。本文 FPGA 不负责完整 TCC 生成或特征分解。

## 5. 绘制传统 CPU-SOCS 流程

传统流程按以下五个节点绘制。

### CPU-(a) 输入掩模

图像：二值 mask。

下方标注：

```text
1024×1024 mask
```

### (b) 掩模频谱与 SOCS 核

图像：掩模频谱幅值图，右下角可叠放 3 至 5 个 SOCS 核缩略图。

箭头说明：

```text
Load M̂, Φk and σk
```

### (c) CPU 逐核频域计算与二维 IFFT

节点内部建议用三联小图：

```text
17×17 mask window × 17×17 kernel
                ↓
128×128 frequency grid
                ↓
CPU FFTW 2D IFFT
```

在节点外侧画一个循环箭头，标注：

```text
for k = 1 ... Nk
```

该循环必须明确表达 CPU 对每个核重复执行：

1. 读取第 $k$ 个核和权重。
2. 计算 $\hat{M}\Phi_k$。
3. 嵌入固定 FFT 网格。
4. 调用 CPU FFTW 二维 IFFT。
5. 计算 $|E_k|^2$。

### (d) CPU 强度加权累加

图像：10 核部分和或最终 128×128 累加强度图。

箭头或节点说明：

$$
I\leftarrow I+\sigma_k|E_k|^2.
$$

节点下方标注：

```text
Software loop and memory accesses
```

### (e) 最终空中像

图像：傅里叶插值后的 1024×1024 SOCS 空中像。

在 `(d)` 到 `(e)` 的箭头上标注：

```text
FFTshift + Fourier interpolation + crop
```

在整条 CPU 流程右侧标注性能：

```text
35.6 ms / 10 kernels
CPU C++ online SOCS
```

## 6. 绘制本文 CPU-FPGA 协同流程

本文流程使用相同的五个视觉位置，但突出数据搬运和硬件流水线。

### FPGA-(a) 输入掩模

使用与 CPU 流程完全相同的二值 mask。

### (b) 可复用在线输入数据包

图像由三部分组成：

- 掩模衍射谱 $\hat{M}$；
- SOCS 本征核集合 $\{\Phi_k\}$；
- 特征值权重 $\{\sigma_k\}$。

从 `(b)` 到 `(c)` 增加一个窄的橙色传输节点：

```text
PCIe XDMA H2C
```

传输后可增加小标签：

```text
FPGA DDR
```

### (c) FPGA 频域嵌入与二维 IFFT

这是本文流程中视觉权重最大的节点，建议宽度约为普通节点的 `1.3` 至 `1.5` 倍。

节点内部按以下顺序绘制：

```text
17×17 valid frequency product
                ↓
Fixed 128×128 FFT-grid embedding
                ↓
Row IFFT
                ↓
BRAM transpose
                ↓
Column IFFT
                ↓
Block-floating-point compensation
```

节点旁标注：

```text
Pipelined hardware datapath
```

不要在坐标尚未统一前标注 `center embedding`，先使用 `fixed-grid embedding`。

### (d) FPGA 强度计算与片上累加

图像：与 CPU `(d)` 使用同一色标的 128×128 中间强度结果。

节点内部标注：

```text
|Ek|²
  ↓
σk weighting
  ↓
BRAM accumulation
  ↓
FFTshift
```

节点下方标注：

```text
Kernel time multiplexing, intra-kernel pipelining
```

从 `(d)` 到 `(e)` 增加两个窄节点或箭头标签：

```text
AXI-MM writeback -> PCIe XDMA C2H
```

### (e) Host FI 最终空中像

先显示一张小型 `128×128 FPGA output`，再通过箭头连接至主图 `1024×1024 final aerial image`。

箭头标注：

```text
Host Fourier interpolation
128×128 -> 1024×1024
```

在整条 FPGA 流程右侧标注：

```text
10.57 ms / 10 kernels
FPGA online reconstruction kernel
```

旁边可补充：

```text
3.37× speedup vs. CPU C++
```

`10.57 ms` 只代表 FPGA 在线内核，不要把它画成包含 PCIe 和 Host FI 的端到端时间。

## 7. 添加主要贡献标注

建议用四个编号标注本文贡献，避免在节点中堆积长句。

| 编号 | 标注位置 | 文本建议 |
| --- | --- | --- |
| C1 | 离线分支与在线路径边界 | Offline/online workload decoupling |
| C2 | 17×17 到 128×128 节点 | Fixed-grid frequency embedding |
| C3 | FPGA 二维 IFFT 节点 | Area-efficient 2D IFFT datapath |
| C4 | FPGA 累加和接口节点 | BRAM buffering and multi-AXI data movement |

中文版本可写为：

- C1：离线光学预处理与在线重构解耦。
- C2：有效 SOCS 频域窗口到固定 FFT 网格的嵌入。
- C3：面积优化的块浮点二维 IFFT 数据通路。
- C4：片上 BRAM 累加、多 AXI-MM 接口和 PCIe XDMA 集成。

## 8. 视觉规范

### 8.1 颜色

- CPU 软件模块：浅灰色或中性灰。
- FPGA/HLS 模块：浅蓝色。
- PCIe/XDMA 数据传输：橙色。
- 输入与最终结果：浅绿色或无填充。
- 离线可复用数据：灰色虚线边框。
- 在线热点：较粗蓝色边框。

### 8.2 图像

- 所有热力图使用相同色图，建议 `viridis` 或 `turbo`，不要混用。
- 对复数频谱显示 $\log(1+|X|)$。
- 对强度图显示线性强度，并统一 `vmin` 和 `vmax`。
- 不在流程缩略图中放 colorbar；在图注中说明归一化规则。
- 所有图像去除坐标轴、刻度、标题和大面积空白边缘。
- 输入、CPU 输出和 FPGA 输出保持相同的空间方向。

### 8.3 字体与线条

- 中英文分别使用论文统一字体。
- 节点标题字号一致，性能数字可加粗。
- 箭头线宽一致，数据复用使用虚线，主在线路径使用实线。
- 避免圆角过大、阴影和渐变背景。

## 9. 绘制完成后的核对顺序

1. 检查上下两条流程是否采用同一输入和输出定义。
2. 检查 SOCS 核与权重是否被标为离线生成、跨窗口复用。
3. 检查 FPGA 路径是否只包含在线重构，不包含 TCC 构建和特征分解。
4. 检查 CPU 与 FPGA 是否都包含复乘、二维 IFFT、强度平方和权重累加。
5. 检查 Host FI 是否在 FPGA 内核之外。
6. 检查 `35.6 ms` 与 `10.57 ms` 的比较口径是否一致。
7. 检查 17×17 有效窗口、128×128 在线网格和 1024×1024 最终图像尺寸。
8. 检查所有中间图像的方向、色图、归一化范围和裁剪区域。
9. 检查图注是否区分硬件实现误差与 SOCS 截断误差。
10. 导出矢量 PDF/SVG，并额外导出 300 dpi PNG 供 Markdown 预览。

## 10. 推荐图注

> 传统 CPU-SOCS 与本文 CPU-FPGA 协同 SOCS 空中像重构流程对比。上方流程由 CPU 软件循环完成逐核频域复乘、二维 IFFT、强度计算、特征值加权累加和傅里叶插值；下方流程将相同的在线 SOCS 重构算子映射到 FPGA，在固定 $128\times128$ 网格上完成频域嵌入、二维 IFFT、片上加权累加、FFTshift 和结果写回，并由 Host 完成 $128\times128$ 到 $1024\times1024$ 的傅里叶插值。SOCS 本征核和特征值权重由 CPU 离线生成，并在相同光学配置下跨掩模窗口复用。
